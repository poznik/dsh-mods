# Мод `session-cost` — память реализации

Пакет: `@local/session-cost`, бандл профиля `desktop` (подключён как
`link:` на эту папку). Исходный запрос пользователя: кнопка в нижней панели со
стоимостью текущей сессии; по клику — окно с текущим балансом DeepSeek.

Лицензия мода — MIT (как и всего репозитория, см. корневой `LICENSE`).

## Что делает

Одна запись в доке композера под полем ввода:

- кнопка-текст с оценочной стоимостью сессии (`$0.816`) — без иконки;
- в пиковые часы рядом появляется оранжевая стрелка вверх (`↑`) с подсказкой;
- клик открывает модальное окно «Баланс DeepSeek»: стоимость сессии, разбивка
  токенов (ввод без кэша / из кэша / вывод), баланс аккаунта (пополненный и
  бонусы, каждая сумма в валюте кошелька), ссылки «Пополнить» / «Использование»,
  кнопка «Обновить»/«Повторить», сноска с тарифами.

## Где именно в UI

- Слот: `conversation.composer.dock` (полоса под карточкой композера, центр,
  `gap: 12px`), регистрация: `id: 'session-cost'`, `order: 2`, `locale:
  'sessionCost'`. Соседи: `activity` (0), `usage` (1) от `ui-conversation`, после
  слота рендерится штатный контекст-метр.
- Окно — `createPortal` в `document.body` (в доке нельзя: композер обрезает
  фиксированные оверлеи), фон-подложка + центрированная панель.
- Стили — `<style>` внутри компонента, классы с префиксом `dsh-session-cost-`,
  только токены темы; никаких импортов клиентских пакетов DSH.

## Источники данных

| Что | Откуда |
|---|---|
| Токены сессии | клиентская проекция `tokenUsage` (штатный `dsh-token-meter`): `uncachedInputTokens`, `outputTokens`, `cacheReadTokens`, `cacheWriteTokens` — накопленные за всю сессию |
| Баланс | Remote-метод `account.getBalance(clientMeta)`; `clientMeta` — из `accountUi.clientMetadata(locale)`, иначе локальный fallback с версией `1.0.0` |
| Ссылки на Platform | `accountUi.getSnapshot().view.links` (`topUpUrl`, `usageUrl`), если сервис есть |
| Метка пика | локальные часы браузера → UTC |

Namespace `remote.account` читается **двумя путями** (см. грабли): через
`ctx.inject(['remote.account'], …)` со скоупом, который живёт пока сервис
доступен, и через inject-free `ctx.get('remote.account')`. Если ни одного нет —
кнопка стоимости работает, окно пишет «нет доступа к аккаунту».

## Константы и правила (в `client.js`)

- `PRICES` — пиковые ставки DeepSeek V4.1 Flash, USD за 1 млн токенов:
  `cacheMissInput: 0.3`, `cacheHitInput: 0.006`, `output: 1.2`.
  Непик — половина. Проверено по <https://api-docs.deepseek.com/quick_start/pricing>
  (2026-11): flash: hit 0.003/0.006, miss 0.15/0.3, output 0.6/1.2 (непик/пик).
- `PEAK_HOURS_UTC = [[1,4],[6,10]]`, `PEAK_WEEKDAYS_ONLY = true` — официальные
  пиковые окна: 01:00–04:00 и 06:00–10:00 UTC, Пн–Пт; выходные целиком непик.
  Для Самары (UTC+4): 05:00–08:00 и 10:00–14:00.
- Праздники КНР **не учитываются** — Platform считает их непиком, метка идёт по
  расписанию будней (записано в README и комментарии к константе).
- Оценка всегда в USD (`formatUsd`: <0.01 → 4 знака, <1 → 3, иначе 2); балансы —
  в валюте кошелька (`¥`, `$`, иначе код валюты).
- Стоимость всегда считается по пиковым ставкам: это верхняя оценка, половинный
  непик не применяется, потому что история запросов не несёт времени ставки.
- Пока `tokenUsage` неизвестен (провайдер не сообщил usage) — запись не
  рендерится вообще (не `$0.00`).

## Проверка

```powershell
pwsh -File tools/run-check.ps1 -Path session-cost/test/check.mjs
```

Проверка покрывает:

- парс-совместимость модуля (фактически — загрузка и `apply` с заглушками);
- триггер: текст с правильной стоимостью, `aria-label`, `title`, отсутствие глифа
  вне пика, `aria-haspopup="dialog"`;
- метку пика на границах окон: 00:59 / 01:00 / 03:59 / 04:00 / 05:59 / 06:00 /
  09:59 / 10:00, выходной, aria-label с «пиковые часы»;
- окно: ровно один ребёнок портала (подложка) → ровно панель `role="dialog"`,
  `container === document.body` (иначе тест падает), весь русский текст, суммы,
  `role="status"` + `aria-live="polite"`, подсказка о бонусах, строка пика;
- ветку ошибки: локализованная строка + сырое сообщение + «Повторить»;
- скрытие записи при отсутствии `tokenUsage`;
- чтение баланса: `ready` / `signed-out` / `failed` / namespace отсутствует /
  inject-free путь.

Живая проверка: `cordis_inspect_query` → client `Slots.listSubTree`
(`root: conversation.composer.dock`) → `session-cost` в `occupants`, `active: true`.
После правки `client.js` — touch файла и пауза ~8 с.

## История решений и багов

1. **Плагин не был нужен Host-сервис**: всё на клиенте, Host-половина пустая.
   Цена попытки сделать Host-проекцию стоимости (zod-схемы, `wire.view`) — лишний
   код; `tokenUsage` уже отдаёт суммы на клиент.
2. **`createPortal` с неверным контейнером** (сдвинутая скобка: `document.body`
   уходил в детей): React бросал исключение при открытии, слой слотов снимал
   запись — кнопка исчезала по клику. Исправлено разбиением на `panel` →
   `backdrop` → `createPortal(backdrop, document.body)`; тест теперь требует
   контейнер и структуру.
3. **`cannot get property "remote.account" without inject`**: читал
   `ctx.get('remote').account`. Заменено на inject-скоуп + `ctx.get('remote.account')`.
4. **Метка валюты на кнопке**: сначала рисовал монету с ¥ перед суммой — убрано
   по просьбе пользователя, кнопка только текст. Из иконки плагина символ ¥ тоже
   убран (осталась монета).
5. **«Предоставленный баланс»** непонятно — переименовано в «Бонусы DeepSeek» +
   подсказка «списываются раньше ваших пополнений» (официальное правило
   списания: сначала granted, затем topped-up).
6. **Пиковые часы** добавлены как индикатор (оранжевая стрелка вверх +
   подсказка + строка в окне); часы перепроверяются каждые 30 с, чтобы метка
   появлялась/исчезала без перезагрузки.

## Ограничения и что можно улучшить

- Ставки — константа, не из API; при смене прайса правится `PRICES`.
- Нет учёта праздников КНР; нет половинного непика в расчёте.
- Валюты кроме CNY/USD печатаются кодом (`EUR 3.50`).
- Бонусные кошельки показываются отдельной строкой, даже если сумма 0.
- Без браузерного управления внешний вид (контраст оранжевой стрелки, отступы)
  проверяется только пользователем.
- Идеи на будущее (не заказаны): индикатор «до пика/до непика N часов»,
  настройка тарифов через Config, разбивка стоимости по ходам.
